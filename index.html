Sieve: AI-assisted triage of static analysis findings

Static analyzers report hundreds of possible vulnerabilities in a code base, many of them false positives and duplicates. Sieve groups the duplicates, checks each finding with an LLM, scores its severity, and turns the findings a person approves into reports.

What Sieve does, and for whom

Sieve is for security researchers who review public source code, such as hunters on open-source bug bounty programs. It runs on the researcher's own machine and only scans repositories they list as allowed. A person approves every finding before anything is exported.

  1. ScanSemgrep, Bandit, SpotBugs, ESLint and Gitleaks run as plug-ins, each in its own container, and their SARIF output becomes one finding format.
  2. Group duplicatesFindings of the same issue, from different tools or repeated scans, are grouped, and a finding that was already reviewed isn't shown again.
  3. AI triageAn LLM decides whether each finding is a true or false positive, explains why, and cites the code it relies on.
  4. SeverityThe LLM chooses the CVSS v4.0 metrics with a reason for each, and Sieve computes the score with FIRST's algorithm.
  5. Review and reportThe researcher approves, rejects or edits each finding. Only approved findings with approved text are exported as Markdown reports.

We evaluate it on OWASP PyGoat, WebGoat and Juice Shop, the OWASP Benchmark for Java and Python, and real CVEs.
